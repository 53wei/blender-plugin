## 本次验收范围

0.8.0 验收的是第一条可安装的 AI 辅助建模竖向闭环：用户描述转接板用途，检查即将发送的
数据，AI 在缺少尺寸时提出测量问题，用户补充后得到严格设计候选，再由本地规则检查、用户
确认、事务创建和实际网格验证。没有 API 时，用户仍可直接填写尺寸并完成同一创建事务。

本报告不把任意零件建模、照片识别、创建后自然语言修改、导出或真实打印列为已完成能力。

## 关键安全边界

- 点击“整理需求”只生成本地发送预览，不联网、不创建对象；
- 用户点击“同意并调用 AI”后才启动隔离网络子进程；
- API Key 不进入模型消息、命令行、`.blend` 或日志；
- AI 返回只会先转换为候选参数，不直接执行 Python 或调用 `bpy` 建模；
- 候选必须通过本地 Schema、零件结构和几何检查；
- 用户再次点击“确认并创建”后，才进入既有事务与 executor；
- 参数变化会使旧确认失效，失败会保持场景不变或回滚；
- 当前不能可靠表达的孔型或零件结构返回明确“不支持”，不做近似生成。

## UI 检查

首屏只保留需求输入、一个主要按钮“整理需求”和一个次要离线入口；AI 服务设置默认折叠。
缺少尺寸时单独显示“要量什么”和“为什么”，保留返回路径和直接填写尺寸的替代路径。AI
工作中、成功和失败都有文字状态，失败提示包含重试方向。右下角助手仍固定为 92 × 92 像素，
不会成为场景物体。

视觉检查文件由开发流程保存在本机 `.impeccable/review/`，不进入发布 ZIP。

## 尚存风险

1. 本次联网闭环使用本机可控的 OpenAI-compatible 模拟服务，验证了真实 HTTP、严格输出格式、
   子进程和 UI 状态，但没有把任何私人远程 API Key 写进测试。不同兼容服务和模型的结构化
   输出质量仍需单独评测。
2. 当前正式零件族仅支持矩形转接板与两组语义固定的双孔；其他几何会明确拒绝。
3. 创建后自然语言修改尚未连接安全网格修改事务；`parameter_patch` 不会被界面执行。
4. 尚无照片尺寸恢复、尺寸标注、STL/3MF 导出、切片器联动和真实打印试装证据。
5. 本机没有安装 Ruff，因此未执行 Ruff 检查；`compileall`、149 项测试、Blender 集成和安装版
   回归均已通过。

结论：0.8.0 可以称为“第一个经过开发者测试的 AI 辅助转接板建模闭环”，不能称为“任意零件
自动建模完成”或“已经验证可打印”。
