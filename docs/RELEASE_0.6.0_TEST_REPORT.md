测试环境：Windows，Blender 4.5.12 LTS

## 本次发布范围

0.6.0 增加受约束的 AI 结构化规划，但不增加新的 Blender 写动作。模型只能提出已有的 `place_on`、`move`、`lock` 和 `unlock`，所有场景变化仍通过原有事务、执行器和验证器。

正式用户流程：

```text
中文指令
→ 本地解析优先
→ 本轮发送数据审查
→ 用户同意调用 AI
→ 隔离子进程请求候选 JSON
→ Blender 主进程二次校验
→ 计划预览
→ 用户确认执行
→ 事务修改
→ 结构化验证或回滚
```

## 已验证的失败边界

- 未经用户同意不会发送 AI 请求。
- 远程 HTTP、带账户信息或查询参数的地址被拒绝。
- Blender 禁止联网时不启动请求。
- 认证失败、限流、服务错误、超时和取消不会修改场景。
- 模型连续两次输出无效 JSON 后停止，不无限重试。
- 未知字段、任意 Python、未知动作、错误对象 ID、重复动作 ID 和超限位移被拒绝。
- 模型不能设置计划 ID、来源、场景指纹或确认标志。
- 模型返回期间相关对象被修改时，旧计划因 `PLAN_STALE` 被拒绝。

## 尚未验证的风险

- 自动化使用本机模拟 OpenAI-compatible 服务，不代表所有第三方兼容服务都实现相同接口。
- 尚未用多个真实云模型建立成功率、费用和输出兼容性矩阵。
- 尚未让外部用户用自己的资产完成任务；当前结果只能称为开发者测试。
- 当前白名单不包含建模、材质、灯光、相机、旋转、对齐或分布。
- 表面摆放只支持可以用水平世界坐标边界框可靠表达的网格支撑面。

## 对外展示时的准确说法

可以说：“独立设计并实现了一个可安装的 Blender AI 场景规划 MVP。模型只生成受限结构化计划，用户确认后由本地事务执行并验证；取消、无效输出和过期结果都不会修改场景。”

暂时不要说：“已经支持任意 Blender 建模”“所有模型服务都兼容”或“已经获得用户验证”。
