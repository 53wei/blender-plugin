# 场景智能助手产品实施计划

状态：0.6.2 阶段 3 本机真实模型首次验收，真实资产及外部用户验收待完成  
日期：2026-10-07  
目标环境：Blender 4.5 LTS 起步  
目标版本：1.0 可公开测试产品

> 2026-10-14 更新：`feature/guided-scene-workflow` 先补齐“导入已有模型 → 本地安全摆放 → 相机取景 → PNG 导出”。布局、旋转、缩放和相机先以明确 UI 控制交付，AI 白名单继续保持 `place_on/move/lock`。纯 Python 测试已扩展到 100 项；Blender 后台与真实窗口验收待完成。详细边界见 ADR 010。

## 1. 先说明现在做的是什么

0.6.2 已适配本机 LM Studio 的 JSON Schema，并在 Blender 4.5.12 中实际调用 Qwen 验证预览、确认执行及固定合成任务。初始全量 18/20；澄清移动对象与保留对象的区别后，一轮 20/20（AI 正向任务 8/8）。这只是受限开发者测试；不代表真实资产、任意构图或外部用户验证。下一道门禁是作者用真实资产记录 5 条任务与手动耗时对照，而不是继续堆未验证的动作。见 `RELEASE_0.6.2_TEST_REPORT.md`。

0.6.1 补充了本地可信动作预览、禁止 AI 自行解锁，以及 20 个固定任务的独立评测入口。本轮仍完善阶段 3，没有提前进入新增动作阶段。离线回放和模拟接口不等于真实模型能力；下一道验收是选定真实服务、限额试跑、记录错误，再测试自己的真实资产。具体步骤见 `MODEL_EVALUATION.md`。

0.3.0 是最终产品下面的“确定性执行与安全底座”。截至 0.6.0，阶段 1 的产品外壳、阶段 2 的 BYOK/Provider 基础设施和阶段 3 的 AI 结构化规划 MVP 均已落地。当前已经具备：

- 严格的 ActionPlan 动作协议。
- 计划预览、用户确认、场景指纹和过期计划拒绝。
- 事务执行、失败回滚和结构化结果验证。
- 已有物体的表面摆放、定距移动、锁定和解除锁定。
- 一个可点击的视口助手形象、中文对话式面板和本地明确指令解析器。
- 待机、数据确认、AI 规划、计划确认、工作、成功和错误七种可见状态。
- Provider 中立契约、OpenAI-compatible 连接测试和会话级 Key。
- 隔离网络子进程、非阻塞轮询、取消、超时与稳定错误分类。
- Key 不进入 `.blend`、命令行、日志或模型消息。
- AI 调用前显示本轮发送数据，并要求用户逐次同意。
- 最小场景上下文、结构化候选计划、一次 JSON 修复和本地主进程二次校验。
- AI 计划仍需用户确认，并继续经过事务、执行器、验证器和回滚层。

当前没有实现：

- 新建或编辑网格、材质、灯光和相机。
- `align`、`distribute`、`rotate` 等多物体编排动作。
- 基于截图的视觉构图判断和反馈循环。
- 自动执行模式与服务端费用估算。

因此，0.6.0 已是可以安装和演示的 AI 规划 MVP，但还不能被描述成完整的自动建模或多物体构图产品。

## 2. 最终产品定义

用户安装插件后，3D 视图右下角出现一个不属于场景内容的二维动态助手形象。点击形象后打开原生 Blender 助手面板。用户输入类似：

> 把桌子放在画面中央，台灯放右边，椅子稍微朝向桌子，镜头用偏广角并保持桌子是视觉重点。

插件执行以下流程：

```text
用户指令
  → 本地解析器优先
  → 展示本轮最小场景摘要
  → 用户同意发送
  → 调用用户选择的 AI 模型
  → AI 只返回白名单结构化计划
  → 本地验证与空间求解
  → 显示计划摘要
  → 用户确认或安全模式自动确认
  → 事务化操作 Blender
  → 自动验证、失败回滚
  → 助手显示完成结果或可理解的错误
```

助手形象默认是视口叠加层，不创建真实 3D 物体，避免污染用户场景、导出内容和渲染结果。

## 3. 产品交互设计

### 3.1 助手形象

形象固定在 3D 视图右下角，可关闭、缩放和更换位置，包含以下状态：

- 待机：轻微呼吸或眨眼。
- 聆听：输入框已打开。
- 思考：正在等待模型返回计划。
- 工作：正在逐步执行 Blender 动作。
- 成功：显示完成反馈。
- 警告：需要用户确认或补充信息。
- 失败：说明失败原因以及场景是否已恢复。

第一版使用项目专用的原创 PNG 助手图像，不使用实际 3D 角色。0.4.0 使用 `POST_PIXEL` GPU 叠加按实际像素绘制形象，并以透明的 Blender 原生 `GIZMO_GT_button_2d` 提供点击、悬停和工具提示。

### 3.2 对话面板

点击形象后打开浮动“场景领航员”面板；也可从 `N → BSA` 进入，包含：

- 简短对话历史。
- 指令输入框和发送按钮。
- 当前模型、连接状态和取消按钮。
- AI 生成的计划摘要。
- “确认执行”“修改要求”“取消”按钮。
- 执行进度、验证结果和恢复状态。
- 本轮发送给模型的数据预览。
- Token、延迟和可获得时的费用信息。

Blender Python UI 不是网页环境，因此外观可以接近 Codex 的交互逻辑，但不会像桌面 Web UI 一样支持完整 Markdown、复杂动画和任意布局。

### 3.3 执行模式

- 安全模式：所有场景修改都需要确认，默认开启。
- 辅助自动模式：经过验证的低风险动作可自动执行。
- 破坏性或不确定动作：无论模式如何都必须确认。

第一版只发布安全模式。收集真实用户证据后再开放辅助自动模式。

## 4. 技术栈

| 层级 | 技术选择 | 作用 |
|---|---|---|
| 插件形态 | Blender Extension、Python | 本地 ZIP 安装与扩展分发 |
| Blender 交互 | `bpy`、`mathutils` | 读取和修改场景 |
| 助手形象 | `gpu`、`bpy.utils.previews`、`GIZMO_GT_button_2d` | 绘制可点击的视口二维形象和状态 |
| 原生界面 | `Panel`、`Operator`、`PropertyGroup`、`AddonPreferences` | 对话、设置、计划和结果面板 |
| 场景中间表示 | 纯 Python dataclass | 隔离 Blender 对象与模型输入 |
| 动作协议 | 严格 JSON ActionPlan | 禁止模型直接执行 Python |
| 本地求解 | AABB/OBB、约束求解、相机投影计算 | 把语义计划转换成确定坐标 |
| AI 适配层 | `PlannerProvider` 接口 | 隔离不同模型提供商 |
| 首个模型接口 | OpenAI-compatible HTTP API | 兼容云端或本地兼容服务 |
| 网络实现 | 标准库 HTTP 起步；独立工作进程可行性验证 | 避免阻塞 Blender 主界面 |
| 主线程调度 | `bpy.app.timers` + 消息队列 | 仅在 Blender 主线程读取和修改 `bpy` |
| 密钥管理 | 会话内存、环境变量；后续 OS 凭据库适配 | 不把 Key 写入 `.blend` 和日志 |
| 测试 | `unittest`、Blender background、模拟 Provider、固定 `.blend` | 单测、集成和端到端验证 |
| 发布 | Extension ZIP、GitHub/官网；官方平台单独评估 | 完整 AI 版和平台版分渠道发布 |

网络实现必须先做技术验证。Blender 官方文档警告 Python 线程可能造成难以诊断的崩溃，因此网络层不得在后台线程访问 `bpy`；优先评估短生命周期独立进程，主线程只轮询结构化结果。

## 5. AI 与 Blender 的职责边界

### AI 负责

- 理解用户的自然语言和模糊场景意图。
- 从场景摘要中识别相关物体。
- 选择白名单动作并填写参数。
- 解释计划和失败原因。
- 在允许的最大次数内根据验证结果重新规划。

### 本地程序负责

- 对象 ID、单位、坐标和边界框。
- 精确摆放、碰撞间隙、对齐和分布。
- 相机位置、目标点、焦距和取景计算。
- 动作协议校验、锁、检查点和场景 diff。
- 实际调用 `bpy` 修改场景。
- 验证结果和失败回滚。

### AI 永远不能做

- 返回任意 Python 并直接执行。
- 绕过 ActionPlan、validator、transaction 或 verifier。
- 静默上传完整 `.blend`、网格、纹理或 API Key。
- 自动解除用户锁定的物体。
- 在验证失败后假装成功。

## 6. BYOK 设计

用户自己提供 API Key、服务地址和模型名称。插件提供：

- Provider 类型。
- API Base URL。
- 模型名称。
- 临时 API Key 输入框。
- “测试连接”按钮。
- 是否允许发送低分辨率预览图的开关。
- 本轮实际发送数据的预览。

第一版密钥策略：

1. 默认只保存在当前 Blender 会话内存。
2. 支持从环境变量读取。
3. 不写入 `.blend`、项目目录和日志。
4. 不默认保存到 Blender 普通首选项，因为其中的明文密码保护不足。
5. 后续为 Windows Credential Manager、macOS Keychain 和 Linux Secret Service 实现可选适配器。

## 7. 模型输入与隐私

默认只发送：

- 当前用户指令。
- 最多 20 个相关可见对象的 ID、名称、类型、尺寸、位置和锁状态。
- 支持的动作 schema。

默认不发送：

- 完整 `.blend` 文件。
- 顶点、UV、材质贴图和资产文件。
- 全部场景历史。
- API Key。
- 未经用户允许的截图。

需要视觉构图判断时，可以生成低分辨率临时预览图。第一次发送图片前必须明确告知并获得用户同意。

## 8. 分阶段实施计划

### 阶段 0：产品方向重置与现有底座冻结

预计：2—3 天。

任务：

- 把 0.3.0 定义为“确定性执行核心原型”，不再称为完整产品。
- 冻结现有 ActionPlan、事务、回滚和验证测试。
- 确认新产品名；官方平台版本名称不能含“Blender”。
- 完成助手形象、面板和执行流程线框图。

验收：团队能用一张流程图解释用户从点击形象到结果验证的全过程。

### 阶段 1：产品外壳与助手形象（0.4.0 已完成）

预计：1—2 周。建议版本：0.4.0。

任务：

- 实现视口二维助手形象。
- 实现待机、思考、工作、成功、错误五种状态。
- 点击形象打开或定位到助手面板。
- 将当前本地指令功能接入新的对话式面板。
- 增加对话记录、计划卡片、执行进度和取消操作。

验收：不配置 API 也能通过新界面执行当前 0.3.0 的确定性指令。

### 阶段 2：BYOK 与 Provider 基础设施（0.5.0 已完成）

预计：1—2 周。建议版本：0.5.0。

任务：

- 增加 `PlannerProvider`、请求、响应、错误和 usage 接口。
- 先实现一个 OpenAI-compatible Provider。
- 实现会话 Key、环境变量、连接测试、超时和取消。
- manifest 增加 `network` 权限并检查 `bpy.app.online_access`。
- 验证不会阻塞 Blender、不会从后台访问 `bpy`。
- 模拟无效 Key、限流、断网、超时和错误 JSON。

验收：模型不可用时场景零修改；Key 不进入 `.blend` 和日志。

完成证据：43 个纯 Python 测试通过；Blender 4.5.12 LTS 中完成真实本机 `/models` 连接、模型可见性与取消测试；另有保存 `.blend` 后搜索测试 Key、禁用联网和不安全 URL 的场景零修改检查。0.5.0 未调用规划接口，所以上述证据不能描述成“AI 已能摆场景”。

### 阶段 3：AI 结构化规划 MVP（0.6.0 已完成）

预计：2 周。建议版本：0.6.0。

任务：

- 实现场景相关对象筛选与最小 ContextBuilder。
- 定义 PlannerRequest 和严格 JSON 输出格式。
- 模型输出只允许现有 `place_on/move/lock/unlock`。
- 增加一次 JSON 修复机会，第二次失败则停止。
- 显示 AI 计划、相关物体、预计动作和确认按钮。
- 记录调用次数、Token、延迟和错误类型。

验收：用户可以用较自然的说法完成已有动作，但模型仍不能直接操作 Blender。

完成证据：59 个纯 Python 测试通过；Blender 4.5.12 LTS 官方 manifest 校验与 0.6.0 构建通过；在全新隔离用户目录安装 ZIP 后，模拟 Provider 跑通“指令 → 数据审查 → 用户同意 → 候选 JSON → 本地二次校验 → 计划预览 → 用户确认 → 事务执行 → 验证”。本地流程连续 20/20 通过，已安装包的 AI 闭环也连续 20/20 通过。取消、超时、连续无效输出和等待期间相关对象变化均不会产生可执行计划或修改场景。这些只属于开发者测试，不等同于外部用户验证。

### 阶段 4：多物体场景编排能力

预计：2—3 周。建议版本：0.7.0。

新增白名单动作：

- `relative_place`
- `align`
- `distribute`
- `rotate`
- `scale_uniform`
- `arrange_grid`
- `arrange_ring`
- `preserve_transform`

任务：

- 实现多物体约束和碰撞间隙。
- 支持“桌子居中、椅子围绕桌子、灯放右侧”等复合计划。
- 所有新动作先写纯 Python 测试，再连接 Blender。
- 限制单计划动作数量和可移动范围。

验收：固定的书桌、电商陈列和简单房间三个场景能稳定完成编排。

### 阶段 5：相机构图

预计：2 周。建议版本：0.8.0。

新增白名单动作：

- `camera_look_at`
- `camera_frame_objects`
- `camera_set_lens`
- `camera_set_projection`
- `set_render_aspect`

任务：

- 实现目标包围盒投影和取景计算。
- 支持主体居中、三分法、留白、俯视和低机位等有限构图模板。
- 先由本地算法保证主体在画面内，再允许视觉模型评价低分辨率预览。
- 视觉请求必须单独取得用户授权。

验收：相机不会把主体裁出画面；相同场景和计划结果可重复。

### 阶段 6：连续编辑与有限 Agent 循环

预计：2 周。建议版本：0.9.0。

任务：

- 保存当前关注对象和用户硬约束。
- 支持“桌子别动”“灯再往里一点”等连续修改。
- 每轮最多两次重新规划，禁止无限循环。
- 增加有限检查点历史和“一键撤销本轮”。
- 助手形象根据规划、执行和验证阶段切换状态。

验收：至少四轮连续修改中，锁定对象和用户约束始终不被破坏。

### 阶段 7：真实用户 Beta

预计：2—3 周。

任务：

- 招募 5—10 名 Blender 用户使用自己的资产测试。
- 记录原始指令、是否成功、失败分类、修改次数和是否愿意再次使用。
- 与 Blender 手工操作以及普通自由 Agent 比较时间、成功率和可恢复性。
- 根据失败数据决定是否增加动作，而不是凭感觉扩功能。

验收：至少一个具体用户群在重复任务中主动第二次使用。

### 阶段 8：1.0 发布

预计：1—2 周。

任务：

- 生成可复现 ZIP、安装说明、隐私说明和故障排查。
- 制作真实完整操作视频，不只展示最终渲染图。
- 发布架构图、基准测试、失败案例和技术取舍。
- 建立版本升级和兼容性测试矩阵。

验收：陌生用户仅按中文文档即可安装、配置 Key、完成一次任务并恢复失败操作。

## 9. 分发与上架策略

### 完整 AI 版

优先使用：

- 本地 ZIP 安装。
- GitHub Release 或产品官网下载安装。
- 适合允许 BYOK 和外部服务的第三方插件市场。

### Blender 官方 Extensions 平台

截至 2026-09，官方平台要求 GPL 兼容、插件名称不能包含“Blender”、联网必须声明权限并尊重 `bpy.app.online_access`。平台条款还规定，扩展不能以外部购买、注册或 Key 作为阻塞主要功能的前置条件。

因此不能把“完整 BYOK AI 版一定能上官方平台”作为既定结论。可行路线是：

1. 官方平台版在没有 Key 时仍提供完整且有实际价值的离线编排功能。
2. AI 功能作为可选增强，并在提交前向审核方确认是否符合规则。
3. 如果仍不符合，则完整 AI 版走本地 ZIP/官网分发，官方平台不作为首发渠道。

另外，助手图像资产若提交官方平台，需要使用原创可授权资产或 CC0 资产。

## 10. 1.0 必须达到的质量线

- Blender 主界面在模型请求期间保持可操作。
- 模型输出永远不能直接执行 Python。
- 所有场景修改经过同一事务和验证链。
- API Key 不进入 `.blend`、日志和模型请求内容。
- 断网、无效 Key、限流、超时和错误计划都不会修改场景。
- 失败事务能够验证回滚结果。
- 固定端到端任务连续运行至少 20 次无随机失败。
- 至少 5 名外部用户使用自己的资产完成测试。
- README、安装说明、隐私说明、上架材料全部使用中文，并提供必要英文摘要。

## 11. 对实习作品最重要的展示内容

作品重点不是“接了一个模型”，而是证明：

- 你设计了受约束的 AI Agent 架构。
- 你能把自然语言和 Blender 的精确状态修改分离。
- 你处理了密钥、隐私、网络、线程、回滚和验证。
- 你用真实用户与基准数据决定功能范围。
- 你能解释为什么不让模型直接执行 Python。
