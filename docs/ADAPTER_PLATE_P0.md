# 矩形转接板 P0：已实现范围与开发者用法

日期：2026-10-18  
状态：纯 Python 参数核心与 AI 候选协议已完成；尚未接入 Blender 界面和网格执行器。

## 这一轮真正完成了什么

P0 可以把两组或多组安装孔组织成一块矩形转接板的确定性规格。输入包括板宽、板深、厚度、
圆角半径，以及每个安装模式的原点、孔偏移和孔径。输出不是任意网格或 Python，而是后续
Blender 执行器可以消费的稳定参数数据。

本地验证会阻止：

- 零值、负值、`NaN`、无穷大和布尔值冒充尺寸；
- 重复的板、安装模式或孔 ID；
- 没有完整落在板轮廓内的孔；
- 进入圆角切除区域的孔；
- 彼此重叠的孔；
- 修改后因为板过小而暴露到轮廓外的孔。

P0 也支持“修改外形但保持孔的世界位置”。例如从板左边把宽度从 80 mm 增加到 90 mm，孔的
板内坐标不变；如果从右边增加，孔的板内坐标向右移动 10 mm，同时板对象反向移动 10 mm，
所以装配中的孔世界位置仍然不变。中心加长时两者各移动一半。

## AI 可以返回什么

新的候选协议只有三种状态：

| 状态 | 含义 | 本地接下来做什么 |
|---|---|---|
| `needs_input` | 缺少会影响设计的测量 | 显示测量项，不创建模型 |
| `design_candidate` | 一个矩形转接板参数候选 | 本地重新检查所有几何关系 |
| `parameter_patch` | 修改板宽或板深并声明保留孔位 | 与当前可信板 ID 对照后计算修改 |

候选采用关闭字段 Schema。未知零件族、未知字段、任意 Python、API Key、来源、确认标记和伪造
设计指纹都会被拒绝。模型输出即使形式正确，只要孔越界或重叠，也会在本地几何验证中失败。

这一轮没有发起网络请求。现有“设置 → AI 服务”仍是以后唯一的用户自带 API 入口；真正接入时
将复用会话级密钥、调用前数据预览和隔离进程，不会新增第二套密钥保存。

## 开发者演示

```powershell
python demos/run_adapter_plate_demo.py
python -m unittest tests.test_adapter_plate tests.test_print_intent_candidate -v
python -m unittest discover -s tests -p "test_*.py" -v
```

演示会生成一块 80 × 40 × 3 mm 的合成转接板，再从左边加长到 90 mm，并输出修改前后孔位。
这些都是合成数据，不代表已经完成真实打印验证。

## 当前明确不能做什么

- Blender 里还没有“转接板”参数面板，也不会出现新按钮；
- 还没有创建真实板件网格、布尔贯穿孔、尺寸标注、撤销记录或 STL/3MF 导出；
- AI Provider 还没有调用新的零件候选协议；
- 只支持矩形平板和圆形贯穿孔，不支持沉头孔、螺纹、长圆孔、加强筋或自由曲面；
- P0 修改只能保持全部安装模式，不能只固定设备孔而让支架孔自动跟随板边；
- 没有打印、试装和材料补偿证据，因此不能宣称“可打印即装配成功”。

下一阶段应先建立转接板创建计划、事务化 Blender 执行器和独立尺寸验证，再把它接进统一参数
界面。只有这些本地链路通过后，才接入真实 AI 请求。
