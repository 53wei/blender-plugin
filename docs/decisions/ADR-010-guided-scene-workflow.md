# ADR 010 引导式现有模型场景流程

状态：已接受；日期：2026-10-14。

## 背景

0.6.2 已能对场景中的已有对象执行受限自然语言摆放，但非专业用户仍需先在 Blender 外部理解导入器、坐标轴、批量排列、相机和渲染设置。用户当前的第一优先级是先完成“用已有模型快速搭建场景”，3D 打印诊断另作后续方向。继续增加模型自由度不能解决这一段操作断裂。

## 决策

增加一个本地优先的三步引导流程：

1. **模型**：批量导入 `.blend/.fbx/.obj/.glb/.gltf/.stl/.ply`。同一批任一文件失败时移除本批新增对象；成功后自动选中并分配稳定 ID。
2. **摆放**：为所选网格提供落地、以活动物体为基准的边界框对齐、确定性 XY 网格排列、本地单轴旋转和等比缩放。所有变换先生成可信动作清单，用户确认后统一经过 validator、checkpoint、executor 和 verifier。
3. **取景**：根据显式对象集合的联合 AABB 计算透视相机计划，先展示对象、焦距、留白和相机位置，再确认创建或移动相机。PNG 导出临时覆盖分辨率、格式和透明背景，渲染后恢复原设置。

`rotate` 与 `scale_uniform` 加入 Action Protocol 的本地/UI 动作集合；AI 候选协议仍只允许 `place_on/move/lock`，不得借此扩大模型权限。对齐和网格排列在预览阶段被确定性展开为多个 `move`，因此确认清单会显示真实的逐对象位移。

相机取景使用单独的 `CameraFramePlan`，以相关对象 fingerprint 防止预览后场景变化。相机创建/修改由专用 Blender adapter 负责并带恢复逻辑，不允许 UI 直接散落写 `bpy` 状态。

## 备选方案

- 未让 LLM 直接调用 Blender 导入、相机或渲染操作，因为这些步骤有明确参数和本地算法，不需要增加模型调用与权限。
- 未在本轮增加 mesh 修复、材质生成、灯光生成或 3D 打印设置。这些属于新的任务族，应先有独立诊断边界与验收数据。
- 未承诺视觉审美评分。当前相机算法只保证基于边界框的可重复安全取景，最终构图仍需真实 Blender 画面验收。

## 代价与验证

AABB 对旋转复杂模型会产生保守留白；不同导入格式的材质与坐标约定仍由 Blender 官方导入器决定；相机计划不判断主体美感。新增纯 Python 测试覆盖布局、动作协议、事务验证、格式白名单、取景计算和 stale plan；Blender 后台脚本覆盖落地、网格、旋转、缩放和相机创建。真实窗口仍需人工检查文件选择器、三段界面、相机画面边缘和 PNG 输出。
