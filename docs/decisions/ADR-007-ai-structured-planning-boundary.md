# ADR 007 AI 结构化规划与用户确认边界

状态：已接受

日期：2026-10-06

## 背景

0.5.0 已证明用户自带 API、会话密钥、联网权限、隔离子进程、超时和取消能够在不修改场景的前提下工作。0.6.0 需要第一次把自然语言与最小场景摘要发送给模型并生成计划。如果直接让模型返回完整可信 `ActionPlan`，模型就能伪造场景指纹、确认标志和来源；如果点击“发送”后自动上传全部场景，又会破坏数据最小化与用户知情原则。

## 决策

本地解析器始终优先。只有本地解析器返回 `ACTION_NOT_SUPPORTED` 时，界面才准备 AI 请求；对象不存在、对象锁定、前置条件失败等明确错误仍在本地结束，不用模型猜测或绕过。

AI 调用分成两个用户可见步骤：

1. 主线程读取不可变 `SceneSnapshot`，构建本轮最小上下文并显示数据预览。
2. 用户点击“同意并调用 AI”后，才启动隔离子进程。

最小上下文只包含当前指令、场景单位比例，以及最多 20 个候选可见对象的 `object_id`、名称、类型、世界位置、世界尺寸和锁定状态。指令中明确出现名称时只发送匹配对象；没有明确名称时发送按稳定 ID 排序并截断的可见对象。默认不发送矩阵、包围盒、父子关系、完整场景历史、网格、材质、纹理、文件或截图。

OpenAI-compatible MVP 使用 `POST /chat/completions`，请求 JSON 对象输出，温度为 0。模型只返回候选计划：

```json
{
  "schema_version": "0.1",
  "actions": [],
  "constraints": [],
  "user_summary": ""
}
```

候选计划只允许当前已经实现并能验证的 `place_on`、`move`、`lock`、`unlock` 和 `preserve_transform`。模型不能提供 `plan_id`、`source`、`scene_fingerprint` 或 `requires_confirmation`；这些可信字段由 Blender 主进程生成，并强制 `source="llm"`、`requires_confirmation=true`。

候选 JSON 在网络子进程内做第一次严格校验。JSON 或 schema 无效时最多追加一次修复请求；第二次仍无效就返回稳定的 `PROVIDER_OUTPUT_INVALID`，不创建预览。主进程收到候选后再次使用同一纯 Python 解析器校验，并以发起请求时的不可变快照计算相关对象指纹。如果相关对象在等待模型期间发生变化，返回过期错误并要求重新规划，不能把当前指纹补到旧计划上。

网络子进程继续禁止导入 `bpy`。所有模型失败、取消、超时、无效输出和 stale 结果只更新界面状态，不创建可执行计划，不进入事务，也不修改 Blender 场景。用户看到 AI 计划后仍必须点击“确认并执行”，后续继续经过原有 `PlanValidator`、事务、执行器、验证器和回滚层。

每次成功或失败调用记录不含 prompt 的 Provider、模型、总输入 Token、总输出 Token、延迟、请求次数和是否使用修复。0.6.0 不估算价格，因为不同服务和模型价格无法由兼容协议可靠获得。

## 备选方案

- 没有让模型返回完整可信 `ActionPlan`，因为场景指纹和确认要求属于本地安全边界。
- 没有让模型返回或执行 Python，因为这会绕过动作白名单、事务与验证器。
- 没有在首次点击“发送”时自动上传，因为用户必须先看到本轮数据预览。
- 没有发送完整 SceneSnapshot，因为矩阵、包围盒和全部对象对当前四类动作不是默认必需数据。
- 没有无限修复或自动重试，因为这会造成不可控费用、延迟和行为循环。
- 没有默认使用只被部分服务支持的严格 JSON Schema 服务端模式；MVP 使用兼容面更广的 JSON 对象模式，并始终本地严格校验。

## 影响

AI 流程比“一键执行”多一次数据确认和一次计划确认，但用户能明确知道发给第三方的内容，也能在场景修改前审查模型计划。没有在指令中出现对象名称时，最多会发送 20 个可见对象摘要；大型场景需要后续用搜索、选择集或语义索引进一步收缩。

部分 OpenAI-compatible 服务不实现 `/chat/completions` 或 JSON 对象模式，会返回明确不兼容错误。模型即使返回语法正确 JSON，也可能引用错误对象或生成不安全参数；本地主进程校验和事务链仍会关闭失败。

## 验证

- 纯 Python 测试覆盖上下文筛选、字段白名单、20 对象上限和确定排序。
- 候选计划测试覆盖未知字段、未知动作、错误对象 ID、空动作、重复 ID、超限距离和任意 Python 字段拒绝。
- 模拟 Provider 覆盖一次成功、第一次无效后修复成功、连续两次无效、401、429、5xx、超时、取消和 usage 聚合。
- 子进程命令行、repr、结果和日志中找不到测试 Key。
- Blender 集成测试证明 AI 请求前必须出现数据预览；等待、失败、取消和 stale 情况场景零修改；成功只生成预览，确认前场景不变。
- 隔离安装包在 Blender 4.5.12 LTS 中完成“模糊指令 → 数据确认 → AI 候选计划 → 本地预览 → 用户确认 → 事务执行 → 验证通过”的本机模拟服务闭环。
