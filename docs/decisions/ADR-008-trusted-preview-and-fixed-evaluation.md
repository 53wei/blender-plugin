# ADR 008 本地可信动作预览与固定任务评测

状态：已接受

日期：2026-10-06

## 背景

0.6.0 的模拟接口已证明调用和执行链能够工作，但计划预览只展示模型的 `user_summary`。该字段无法证明与真实动作一致；模型还可能通过 `unlock` 绕过用户锁定保护。正式作品还缺少按用户任务独立判定的固定评测入口。

## 决策

0.6.1 保持当前动作执行语义和事务层。执行前预览由纯 Python 本地展示器读取实际动作、约束和快照，显示每个动作的对象、目标、区域、世界坐标位移、米制位移及锁状态。模型摘要只作为建议说明，不能替代真实动作清单。

AI 候选中的 `unlock` 暂时关闭失败，返回既有 `OBJECT_LOCKED` 错误。用户先输入独立的明确本地指令“解除锁定 对象名”，确认后才能继续规划该对象。现阶段没有可靠的对象级自然语言授权器，不用关键词猜测解锁权限。白名单中的 `unlock` 保留给本地解析器，AI 的有效动作集合收缩到 `place_on/move/lock`。

固定评测采用 20 个公开的合成资产任务。每个任务有独立初始状态、自然语言要求、预期路由、最终状态目标、允许变化对象和拒绝条件。评测调用同一规划与执行层，再独立检查用户目标；“事务提交”不能单独视为“任务完成”。

离线回放使用固定候选计划验证链路，不代表真实模型成功率。真实模型模式默认关闭，明确选择模式、地址、模型和请求上限后才使用环境变量 Key；首轮最多 2 次 HTTP 请求，完整评测上限可由用户配置。预览模式只打印合成任务的发送数据。结果记录模式、版本、任务集哈希、耗时、请求/修复次数、Token、拒绝和最终目标检查；不保存 Key、模型正文或用户私有场景。

## 备选方案

- 未采用模型摘要作为确认依据，因为摘要与动作之间没有可信一致性保证。
- 未采用“出现解锁二字即授权”，因为否定句、其他对象和模型建议都会造成误授权。
- 未把回放结果写为模型成功率，因为回放没有进行真实推理。
- 未直接开始 0.7.0 新动作，因为现有能力需要先有可重复的任务评测证据。

## 影响

计划预览更详细；涉及锁定对象的复杂指令需要先单独解锁。真实模型测试需要用户选定服务和额度边界。20 个合成任务仍不能代替真实资产测试、手工对照和外部用户反馈。

## 验证

- 模型摘要与动作故意不一致时，预览必须显示实际移动对象与参数。
- AI 解锁候选在本地主进程被拒绝，本地明确解锁仍可用。
- 评测中故意给出错误方向或额外修改对象，即使事务验证通过，任务仍必须失败。
- 缺少真实测试配置时无网络请求，报告不能标记为真实模型模式。
- 在纯 Python 和 Blender 4.5 合成夹具中运行同一固定任务集。
