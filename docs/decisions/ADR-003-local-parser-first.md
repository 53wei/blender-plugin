# ADR 003 M2 先实现本地明确指令解析

状态：已接受

日期：2026-09-29

## 背景

M1 已证明确定性执行、预览、验证和回滚闭环可在 Blender 4.5.12 LTS 稳定运行。用户反馈表明，只提供物体选择字段不符合“场景编辑助手”的产品预期，但直接接入大语言模型会同时引入网络、凭据、费用、隐私和不确定输出。

## 决策

0.2.0 先实现不访问网络的 `LocalIntentParser`。它只解析明确的单步摆放句式，包括源对象名称、目标对象名称、中央/左/右/前/后区域和可选的显式锁定要求。对象名称必须与场景精确对应；模糊语义、未知对象和未支持附加要求全部关闭失败。

解析器只输出现有 Action Protocol v0.1，不直接调用 `bpy`。计划必须继续经过预览、用户确认、validator、transaction、executor 和 verifier。不明确要求锁定时，默认不锁定目标。

## 备选方案

- 不选择立即接入 LLM，因为尚无用户指令数据证明哪些语义需要付费模型，也未完成 BYOK 和隐私设计。
- 不选择对对象名称做模糊猜测，因为选错对象的风险高于让用户修正名称。
- 不选择让文本指令直接生成 Python，因为这会绕过动作白名单、验证和回滚。

## 影响

明确指令可在零模型调用、零网络和可重复测试的条件下完成。用户必须引用场景中真实对象名，暂时不支持指代、审美描述、复合指令和“稍微”等模糊程度词。这些失败会成为后续评估 LLM 边界的真实数据。

## 验证

纯 Python 测试覆盖中英文对象名、区域映射、显式锁定、未知对象、模糊指令、额外要求和同一源/目标。Blender 集成测试必须证明指令生成 `source=local_parser` 的计划，预览不修改场景，确认后通过所有验证。
