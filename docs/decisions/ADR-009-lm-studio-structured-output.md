# ADR 009 LM Studio 结构化输出适配

状态：已接受；日期：2026-10-07。

## 背景

本机 LM Studio 的 `qwen/qwen3-4b-2507` 可列出，但旧客户端发送 `response_format.type=json_object` 时得到 HTTP 400，错误明确要求 `json_schema` 或 `text`。这是传输格式兼容问题，不能作为模型任务能力的结论。

## 决策

0.6.2 在当前 M2 范围增加显式 `output_format` 配置：默认 `json_object` 保持既有服务行为；用户选择 `json_schema` 时发送候选协议的正式 JSON Schema。Blender 会话设置提供中文选择，评测入口提供同名命令参数，隔离工作进程透传配置。

Schema 由候选协议模块生成，关闭额外字段，限定已提供的对象 ID、启用动作、参数结构与现有数值边界。AI 动作仍只有 `place_on/move/lock`，不允许解锁、任意 Python、伪造可信字段。结构约束不能替代本地语义校验、场景指纹、用户确认、事务、验证和回滚。

不自动猜测服务商，也不因 HTTP 400 自动增加重试或改为自由文本。两种模式仍最多一次 JSON 修复，真实评测仍受总请求预算约束。隐私字段、网络权限和 HTTPS/本机回环地址限制不变；本机服务未启用认证时可不输入 Key。

## 备选方案

- 未全局改成 JSON Schema，以免破坏只支持旧模式的兼容服务。
- 未移除返回格式、只靠提示词，因为不能解决需要显式结构化输出的产品需求。
- 未放宽解析器、允许解释文本或脚本执行，因为格式兼容不应扩张执行权限。

## 代价与验证

用户要多选择一个输出格式；服务和模型不支持 Schema 时仍明确失败。新增模式的结构与请求测试先于 UI 接线；测试子进程透传、修复上限和危险输出拒绝。在 Blender 一次性夹具上用实际 Qwen 模型限额试跑，并诚实记录失败及语义错误。通过后构建、隔离安装并更新中文文档。

实测还暴露了两个问题：移动向量的内存字典曾保留元组，严格候选二次解析要求数组；统一 `action_to_dict` 输出列表，保持解析器拒绝非协议结构。模型曾自行计算落面坐标，以及对要移动的 Lamp 添加保持原位约束；补充通用动作语义提示，不向模型发送任务预期答案，也不调整验证器。

全量初测 18/20，两条矛盾约束触发 `POSTCONDITION_FAILED` 并完整回滚；独立内存复诊重现同类模型输出。澄清后第二轮 Blender 全量 20/20、9 次真实本机请求、AI 正向任务 8/8，无跳过或任务范围外修改。两轮报告均保留，不能只展示最终成功率。正式支持仍受当前动作和几何白名单约束。
