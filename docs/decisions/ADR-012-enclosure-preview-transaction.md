# ADR-012：外壳装配预览使用独立的创建事务

- 状态：已接受
- 日期：2026-10-16
- 决策阶段：参数化打印件 P1

## 背景

P0 只能把电路板、安装孔、接口和打印参数转换成确定性的毫米规格，尚未在 Blender
中创建任何物体。现有场景操作协议 0.1 只处理已经存在的物体；它的检查点也只恢复
变换和锁定状态，不能可靠回滚新建物体。

如果把创建外壳直接塞进旧的移动操作，会让“失败后场景不变”这一承诺失效。另一方面，
P1 的目标只是让用户能在 Blender 中检查体积、位置和装配关系，还不能声称已经得到可切片
的最终网格。

## 决策

1. 新增严格类型化的 `EnclosurePreviewPlan`，P1 只允许一个白名单动作：
   `create_enclosure_preview`。不接受 Python、脚本字符串或任意 Blender 操作。
2. 新增独立的 `EnclosurePreviewService` 和 `EnclosurePreviewPort`。所有 Blender 创建、
   删除和属性写入都必须经过这个事务边界，不从 UI 直接调用 `bpy`。
3. 创建前记录完整的既有物体身份集合；本次事务创建的集合与物体使用唯一事务标记。
   失败时只删除带有该事务标记的新对象，并验证既有物体身份及状态没有变化。
4. 纯核心先把 `EnclosureDesign` 展开成可验证的部件清单：底板、四面侧壁、上盖、
   电路板代理、固定柱以及接口开口代理。所有尺寸和坐标仍以毫米表示。
5. Blender 适配器负责根据 `scene.unit_settings.scale_length` 把毫米换算成 Blender 单位。
   非法或不受支持的单位设置必须显式失败。
6. P1 生成的是“装配预览”：固定柱暂为实心圆柱，接口开口是线框代理，侧壁尚未做布尔
   开孔，上盖也尚未加入卡扣或螺丝结构。UI 和文档必须明确它不是可直接打印的最终模型。
7. 提交条件是：部件数量、类型、尺寸、中心坐标和事务标记均通过后置验证；否则自动回滚。
8. P1 不新增聊天界面、HTTP 或模型调用。自然语言只在后续阶段把用户意图转换成同一个
   严格参数协议，不能绕过验证和事务。

## 结果

- 可以在不依赖 Blender UI 的单元测试里证明创建计划稳定、需要确认且可完整回滚。
- Blender 4.5 中可以看到真实的装配尺寸和相对位置，但不会误导用户把预览当作已验证的
  STL。
- 下一阶段 P2 必须在新的 ADR 中冻结布尔开孔、螺丝孔、网格流形检查和导出规则；不得通过
  放宽 P1 验证器来实现。

## 未采用方案

- **直接扩展旧 `SceneEditingService`**：旧检查点不知道如何恢复创建和删除，风险过高。
- **让 AI 生成并执行 Python**：无法审计、无法稳定回滚，也违反白名单动作协议。
- **P1 立即生成可打印网格**：接口布尔、螺丝孔、连接方式和流形验证尚未冻结，无法诚实地
  保证打印成功。
