# ADR-018：转接板创建后安全修改与单步撤销

- 状态：已接受
- 日期：2026-10-19
- 决策阶段：3D 打印零件助手 P4

## 背景

P3 已经打通“描述用途 → 补充测量 → 参数候选 → 确认创建”，但模型创建后只能结束或创建下一
块板。用户前面明确要求继续说“板加长 10 毫米，安装孔位置保持不变”，并看到变化、确认执行、
必要时撤销。如果只在界面中改数值后删除旧对象重建，会绕过 stale 检查、事务回滚和既有场景
保护，也无法证明孔的世界位置没有变化。

## 决策

1. P4 只开放已验证的矩形转接板外形修改：改变板宽和/或板深，并保持全部安装模式的世界孔位。
   厚度、孔径、孔距、孔数量、沉孔、螺纹和自由网格编辑仍不在本阶段支持范围。
2. 创建的板对象保存由本地计划产生的严格参数规格与原点偏移元数据。修改时只接受插件创建、
   元数据完整且实际网格仍与元数据一致的板；手工改坏或伪造的对象返回明确错误。
3. 修改请求允许发送当前板的参数设计，但仍不发送网格、场景其他对象、图片、历史工程或 API
   Key。每轮必须先展示发送预览并取得用户同意。
4. AI 修改只能返回 ADR-013 的 `parameter_patch`。本地使用当前可信规格计算
   `AdapterPlateRevision`，显示修改前后尺寸、固定边、原点补偿和“孔世界位置保持不变”，不能
   让模型直接给最终网格或 Python。
5. 新增关闭字段 `update_adapter_plate_mesh` 计划。计划同时包含修改前设计和修改后设计；确认时
   重新读取实际对象，若修改前设计或网格已经变化则返回 `PLAN_STALE`。
6. Blender 更新必须经过独立更新事务：捕获目标旧网格和非目标对象状态，换入新网格，回读实际
   几何并验证尺寸、圆角、贯穿孔、流形、连通分量、孔世界位置和未授权变化。任何失败恢复旧网格
   并再次验证恢复结果。
7. “撤销本次修改”不直接在 UI 中写 `bpy`，而是把对象元数据中保存的上一版设计构造成反向更新
   计划，仍经过同一确认、事务、执行器和 verifier。P4 只承诺单步版本切换，不承诺无限历史。
8. 修改界面继续采用渐进呈现：成功页给出“继续修改这个零件”；修改页只有需求输入、一个主要
   动作和折叠的 AI 设置；候选页先展示结构化差异，再让用户确认。

## 结果

- 产品从“一次性生成”进入可连续工作的建模工具：创建后可以继续按意图调整外形。
- AI 负责把语言变成受限参数补丁，本地程序负责坐标补偿、替换、验证和恢复。
- 用户可以清楚看到什么会变化、什么必须保持，以及失败时是否已经恢复。
- 代价是当前只支持宽/深修改，且对象必须由插件创建并保持元数据与实际网格一致。

## 未采用方案

- **删除旧对象再调用创建流程**：中途失败会丢失原模型，且无法可靠检查未授权变化。
- **直接修改现有 mesh 顶点**：几何路径复杂、难以验证圆角和孔轮廓，也不利于恢复。
- **把 Blender 全局 Undo 当作唯一历史**：受用户其他操作和上下文影响，不能作为产品事务证明。
- **让模型返回完整更新后设计**：容易静默改变孔位；受限补丁更容易审查和验证。

## 验证

- 纯 Python 测试覆盖确认门、stale 拒绝、宽/深修改、累计原点补偿、孔世界位置保持、未授权变化、
  后置验证失败回滚和反向更新。
- Blender 4.5 集成测试覆盖真实对象网格替换、非目标对象保护、四个贯穿孔与流形回读、失败恢复
  和单步撤销。
- Provider 测试覆盖当前设计最小上下文、发送前确认、严格 `parameter_patch` 和创建请求误返回
  补丁时的拒绝。
