# ADR-016：转接板本地创建界面

- 状态：已接受
- 日期：2026-10-18
- 决策阶段：3D 打印零件助手 P2

## 背景

P1 已能通过受约束计划、创建事务和实际网格回读，在 Blender 4.5 中可靠生成四孔矩形
转接板。但是用户仍需运行开发脚本，无法从插件界面完成一次真实任务。现有“场景领航员”面板面向已有
物体的场景编排，不适合继续堆叠建模参数，也不能让 AI 或自由 Python 绕过 P1 的执行边界。

## 决策

1. 在同一 `BSA` 侧栏增加独立的“3D 打印零件”面板。它不显示聊天记录、AI 服务或场景摆放
   控件；现有场景领航员语义保持不变。
2. P2 只提供“矩形转接板”这一种已验证零件。用户填写板宽、板深、厚度、圆角，以及两组固定
   语义的双孔参数：设备孔组沿 X 轴排列，支架孔组沿 Y 轴排列。任意孔阵列、沉孔、螺纹和
   其他外形返回明确的不支持，不在界面中伪装提供。
3. 界面采用三个可见阶段：`INPUT` 填写参数、`REVIEW` 检查只读摘要、`SUCCESS` 查看实际
   验证结果；执行错误进入 `ERROR` 并给出恢复路径。输入变化必须立即废弃旧摘要。
4. 每个阶段只有一个主要动作。输入阶段的孔位高级参数默认折叠；检查失败时自动展开，避免用户
   找不到需要修改的参数。所有字段使用可见中文标签和毫米单位。
5. “检查参数”只调用纯 Python 参数核心，不修改场景。“确认创建”重新构造并比对当前输入，
   再生成 `AdapterPlateCreationPlan`，通过 `AdapterPlateCreationService` 与
   `BlenderAdapterPlatePort` 写入 Blender。UI 不直接创建、选择或修改对象。
6. 本阶段不接 AI、不联网、不导出 STL/3MF，也不声称已经验证实物可打印。以后 AI 只能填写
   同一严格候选参数，仍必须经过本地检查、用户确认和同一事务执行层。

## 结果

- 用户无需开发脚本即可完成“填写 → 检查 → 确认创建 → 验证结果”的最小闭环。
- 场景在确认前保持不变，输入变化不会执行旧计划。
- 界面不会把“参数合法”误写成“模型已创建”，也不会把网格创建成功误写成“实物打印通过”。

## 未采用方案

- **把转接板参数塞进场景领航员设置页**：会重新造成入口混乱，并把两种产品任务混在一起。
- **一个按钮直接生成**：用户看不到孔位展开结果，失去明确确认边界。
- **让 AI 直接生成或执行 Blender Python**：绕过白名单动作、事务和验证器。
- **首版开放任意数量孔位**：原生侧栏表单会迅速失控，且缺少可靠的列表编辑与测试范围。

## 验证

- 纯 Python 测试覆盖表单到领域规格的映射、摘要、输入指纹、非法孔位和创建计划。
- Blender 4.5 后台测试覆盖注册、检查阶段只读、输入变化使摘要失效、确认创建、真实网格验证和
  注销清理。
