# ADR-013：3D 打印零件意图 AI 与用户自带 API 边界

- 状态：已接受
- 日期：2026-10-18
- 决策阶段：3D 打印零件助手产品方向 V0.1

## 背景

用户确认产品需要 AI，用于理解用途、引导测量、提出结构候选和辅助后续修改；正式发布时由
用户填写自己的 API 地址、模型和密钥。仓库已有安全的 OpenAI-compatible BYOK 设置、连接测试、
会话级密钥、调用前数据审查和隔离网络进程，但它目前服务于旧的场景动作协议，不能直接当作
零件建模协议使用。

打印零件涉及毫米尺寸、孔位关系、装配间隙和制造限制。让模型直接生成 Blender Python 或任意
网格，会破坏确定性、验证和回滚，也无法说明哪些尺寸来自用户测量、默认值或 AI 假设。

## 决策

1. 复用现有 `BSAProviderSession`、`ProviderConnectionConfig`、临时密钥解析和隔离网络进程。
   不新增第二套 API Key 存储，不把密钥写入 `.blend` 或日志。
2. 为打印件建立独立的 `PrintIntentPlanner` 候选协议。AI 只允许返回 `needs_input`、
   `design_candidate` 或 `parameter_patch`，不能直接返回 Blender action 或 Python。
3. 每个已支持零件族拥有自己的关闭字段 Schema、数值范围和关系约束。模型不能通过通用
   `parameters: dict` 添加任意结构。
4. 候选结果由本地主进程二次解析，补齐可信 ID、来源、确认标记和当前设计指纹。用户确认后，
   才能转换成对应的参数化零件计划并进入创建事务。
5. 明确尺寸和参数修改优先本地处理，不调用模型。AI 功能是可选增强；没有 API 不能阻断
   “按尺寸创建”、验证、撤销和导出等本地核心功能。
6. AI 请求前展示本轮发送的数据。照片默认不发送；未来支持图片时，必须逐次显示所选图片、
   用途和隐私提示。关键配合尺寸仍标记为“待测量”，不从图片静默推断。
7. 首个 AI 完整案例使用受支持的矩形转接板；在外壳真实开孔和网格验证完成前，不扩展到任意
   零件生成。

## 结果

- 用户可以继续使用自己的云端或本地 OpenAI-compatible 模型；Provider 替换不会改变几何语义。
- AI 可以改善需求澄清和操作门槛，但本地引擎仍对最终尺寸、关系、事务和验证负责。
- 需要新增零件意图 Schema、候选解析器、数据预览和固定评测；现有场景规划提示词不能复用。
- 插件 manifest 已声明 `network` 权限，但运行时仍必须遵守 Blender 在线访问设置。

## 未采用方案

- **让模型直接执行 `bpy` 或 Python**：无法可靠限制写入范围，也不能证明回滚和尺寸正确。
- **使用一个通用自由参数字典覆盖所有零件**：字段无法封闭，验证器无法知道结构语义。
- **强制用户配置 API 才能建模**：会把本地确定性核心变成付费模型的附属功能，也不利于官方
  分发和离线使用。
- **默认上传照片或完整网格**：超出最小必要数据原则，并增加隐私和成本风险。
