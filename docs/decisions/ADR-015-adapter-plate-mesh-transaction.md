# ADR-015：转接板真实网格与创建事务

- 状态：已接受
- 日期：2026-10-18
- 决策阶段：3D 打印零件助手 P1

## 背景

P0 已经能确定性描述矩形转接板和圆形贯穿孔，但尚未修改 Blender。下一步必须证明它能生成
一个真实、封闭且带贯穿孔的板件，而不是用线框圆柱或自定义属性冒充孔。同时，创建失败、网格
尺寸错误或既有场景变化时必须完整回滚。

## 决策

1. P1 新增唯一白名单动作 `create_adapter_plate_mesh`。计划必须包含已验证的
   `AdapterPlateDesign`，并强制 `requires_confirmation=true`。
2. Blender 执行器使用板的二维外轮廓和反向圆孔轮廓做确定性三角剖分，再沿 Z 轴挤出为一个
   封闭网格。外圆角每个角使用 8 段，圆孔使用 32 段；不调用模型生成脚本，也不使用显示代理。
3. 板局部原点继续位于左前下角。对象位置使用设计中的 `origin_offset_mm`，网格局部坐标保持
   `0..width`、`0..depth`、`0..thickness`。
4. 创建事务在写入前保存既有对象状态。事务只允许创建一个板件对象及其专用集合；任何异常、
   多余对象、尺寸/孔位/孔径不一致、非流形、多个网格连通分量或既有场景变化都必须回滚。
5. 验证器从实际网格重新测量包围尺寸、外轮廓圆角、侧壁轮廓、贯穿孔数量、孔中心和孔径。
   孔 ID 不能只靠自定义属性证明；实际孔轮廓与计划孔做一一匹配。
6. P1 只验证几何闭合、尺寸与受支持关系，不声称已经完成切片、最小壁厚、材料收缩、打印方向、
   STL/3MF 导出或实物装配验证。

## 结果

- 用户确认后得到一个原生可编辑的单一 Blender 网格，圆孔真实贯穿板体。
- 网格结果由独立回读验证，不以“操作没有报错”作为成功标准。
- 固定 8/32 段足以形成开发基线，但以后若要让分辨率成为用户参数，需要新 Schema 和测试。

## 未采用方案

- **板体加线框孔代理**：视觉上像有孔，但不能打印，也无法验证真实拓扑。
- **让 AI 输出 Blender Python**：绕过参数协议、事务和本地验证。
- **连续布尔修改后只检查对象尺寸**：尺寸正确不代表孔存在或网格流形。
- **P1 直接导出并宣称可打印**：缺少切片门禁和实物证据。

## 验证

- 纯 Python 内存端口覆盖确认、重复创建、非法计划、后置失败、未授权变化和回滚失败。
- Blender 4.5 后台测试创建四孔转接板，检查单一连通网格、封闭流形、四个贯穿孔、实际孔位与
  孔径，并故意篡改回读孔径证明完整回滚。
