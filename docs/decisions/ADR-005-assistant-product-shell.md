# ADR 005 可点击助手与对话式产品外壳

状态：已接受

日期：2026-09-30

## 背景

0.3.0 已经具备可靠的本地指令、计划确认、事务执行和结果验证，但主要入口仍是侧栏表单。用户期望安装后能直接看到一个类似桌面智能助手的实体形象，点击后输入场景意图，并在规划、执行和验证过程中获得清晰反馈。本阶段仍受 M1 边界约束，不能为了界面体验提前引入模型、网络或绕过动作协议。

## 决策

0.4.0 将产品名定为“场景领航员”，在 3D 视图右下角显示一个原创 PNG 二维助手。形象使用 Blender `POST_PIXEL` GPU 叠加绘制，透明的原生 `GIZMO_GT_button_2d` 负责稳定点击命中，`bpy.utils.previews` 负责面板缩略图。它不创建场景物体，也不进入渲染或导出。点击形象调用固定宽度的原生浮动界面；`N → BSA` 保留为稳定的备用入口。

界面改为对话式布局，保存当前轮用户消息和助手反馈，显示待机、等待确认、工作、成功、错误五种状态。当前本地解析器生成的 ActionPlan 仍必须由用户确认，所有 Blender 状态修改继续只经过事务和执行器。精确对象与区域字段折叠为备用控制，不删除已有能力。

## 备选方案

- 没有采用真实 3D 角色，因为它会污染用户场景、渲染和导出，也会增加资产与性能成本。
- 没有采用自建事件循环；GPU 叠加只负责按像素绘制形象，点击、悬停和工具提示仍交给原生二维 Gizmo。
- 没有在本阶段模拟 AI 回复或连接模型；界面明确标注当前是离线指令模式。
- 没有删除 `BSA` 侧栏入口，因为 Blender 4.5 的竖排中文分类显示不可靠，且用户需要在隐藏助手形象后有恢复入口。

## 影响

用户安装后可以从视口直接发现产品入口，并在同一面板完成“输入 → 计划 → 确认 → 验证”的闭环。代价是 Blender 原生 UI 无法实现桌面 Web 应用级别的自由布局与动画；当前对话只保留本轮关键信息，助手图像也只有静态状态着色。后续接入 Provider 时必须复用现有状态机，不能让异步网络代码访问或修改 `bpy`。

## 验证

纯 Python 测试覆盖合法状态转换、非法成功跳转和中文状态展示。Blender 源码与隔离安装测试验证资源解码、Gizmo 注册、对话字段、预览只读、确认执行、验证成功和清空复位。带界面的 Blender 验收还需确认助手可见、可点击、能打开面板且不属于场景对象。
