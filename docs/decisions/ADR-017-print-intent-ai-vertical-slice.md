# ADR-017：3D 打印需求 AI 竖向闭环

- 状态：已接受
- 日期：2026-10-18
- 决策阶段：3D 打印零件助手 P3

## 背景

P2 只能让用户手工填写矩形转接板参数，虽然能够可靠创建和验证网格，但没有覆盖产品承诺的
“描述用途、补充关键测量、得到可编辑设计候选”流程。既有场景领航员已经具备 BYOK、隔离网络
进程、发送数据确认和 OpenAI-compatible 接口，但它的提示词与输出协议只适用于场景摆放，不能
直接复用于零件设计。

## 决策

1. 在“3D 打印零件”主面板增加“描述需求”入口。用户也可以跳过 AI，继续使用完整尺寸表单。
2. 每次 AI 请求前必须展示本轮将发送的数据：原始需求、上一轮缺失测量问题和用户补充答案。
   不发送场景对象、网格、`.blend`、图片或 API Key。
3. 复用现有会话级 BYOK 设置、联网权限检查和短生命周期 Provider 子进程；新增零件需求专用
   请求与提示词，不能把场景摆放提示词混入零件设计。
4. AI 只返回 ADR-013 已定义的关闭字段 `PrintIntentCandidate`。P3 界面接受：
   - `needs_input`：展示必须补充的测量及原因，用户回答后再次确认发送；
   - `design_candidate`：只接受当前四孔矩形转接板族，并转换为现有可编辑参数表单；
   - `parameter_patch`：协议仍可解析，但 P3 没有安全网格修改事务，界面必须明确返回暂不支持。
5. `design_candidate` 必须包含 `device` 与 `support` 两个双孔模式。设备孔必须沿 X 轴、支架孔
   必须沿 Y 轴；否则返回 `SPATIAL_UNSUPPORTED_GEOMETRY`，不能近似映射到表单。
6. AI 候选必须再次经过本地 Schema、零件族结构和几何验证。只有转换成 P2 表单并由用户点击
   “确认并创建”后，才能进入原有创建事务和 verifier。
7. AI 调用失败、取消、超时、非法输出或不支持结构时，Blender 场景保持零修改。

## 结果

- 用户可以从一句自然语言需求进入真实 AI 辅助流程，而不是先理解所有建模参数。
- 缺失尺寸不会由模型猜测；用户能看到为什么需要测量，并能连续补充。
- AI 结果最终仍是可编辑毫米参数，不是黑盒脚本或不可解释网格。
- 本阶段完成“需求到首版模型”的闭环，但不冒充已经完成创建后自然语言修改。

## 未采用方案

- **让模型直接返回 Blender Python**：无法限制副作用、验证或稳定回滚。
- **把 P2 默认值当成用户测量值发送**：会让模型把界面示例误当成真实尺寸。
- **收到候选后立即建模**：跳过用户确认，违反既有事务边界。
- **在没有修改事务时接受 `parameter_patch`**：纯参数正确不等于 Blender 网格修改可靠。

## 验证

- 纯 Python 测试覆盖请求最小化、缺失测量、多轮补充、严格候选到表单映射和不支持结构。
- Provider 测试覆盖 JSON Schema、一次修复、Key 不进入请求正文或命令行。
- Blender 4.5 集成测试覆盖发送前零网络/零场景修改、候选填表、确认后事务创建和取消/错误状态。
