# ADR 006 BYOK 与 Provider 子进程边界

状态：已接受

日期：2026-10-01

## 背景

0.4.0 已完成可点击助手、对话式产品外壳和确定性执行闭环。下一阶段需要让用户配置自己的 OpenAI-compatible 服务，但网络请求会带来密钥泄漏、Blender 主线程阻塞、后台线程误用 `bpy`、错误响应污染场景等风险。当前阶段的目标是先证明配置与连接基础设施安全可控，而不是立即让模型生成或执行计划。

## 决策

0.5.0 新增 Provider 契约、OpenAI-compatible 连接客户端、会话凭据和非阻塞连接测试，但不调用模型生成 ActionPlan。

API Key 默认只保存在 `WindowManager` 的会话属性或进程环境变量中，不写入 `Scene`、`.blend`、普通插件首选项、项目文件或日志。远程服务必须使用 HTTPS；只有 `localhost`、`127.0.0.1` 和 `::1` 可以使用 HTTP。URL 不允许包含用户名、密码、查询参数或片段。

网络调用由 Blender 自带 Python 启动短生命周期子进程执行。Key 通过子进程标准输入传递，不进入命令行参数。子进程只接收连接测试所需的 Provider 配置，不读取 Blender 场景，也不能导入或调用 `bpy`。Blender 主线程使用 `bpy.app.timers` 轮询结果，并提供取消与双重超时；所有 Provider 失败只更新连接状态，不触发 ActionPlan、事务或场景修改。

第一版连接测试使用 OpenAI-compatible `GET /models`，只验证地址、认证、基本响应结构和可选模型可见性，不发送场景摘要或用户指令。正式模型规划留到 0.6.0，并继续受严格 ActionPlan 校验约束。

## 备选方案

- 没有在 Blender 主线程直接请求，因为 DNS、TLS 和服务端延迟会冻结界面。
- 没有使用持久 Python 后台线程，因为 Blender 官方明确警告线程生命周期可能造成不稳定，且线程更容易意外接触 `bpy`。
- 没有把 Key 保存到 `AddonPreferences`，因为第一版没有可靠的系统凭据库，明文持久化不符合产品承诺。
- 没有把 Key 放入子进程命令行，因为系统进程列表可能暴露参数。
- 没有在连接测试阶段调用聊天或规划接口，避免产生 Token 费用和把场景数据提前发送给第三方。

## 影响

用户每次新会话需要重新输入 Key，或通过 `BSA_API_KEY` / `OPENAI_API_KEY` 环境变量提供。子进程带来少量启动延迟，但能把网络故障与 Blender 状态隔离，也便于实现取消。部分 OpenAI-compatible 服务如果不实现 `/models`，连接测试会明确报告不兼容，即使其聊天接口可能可用；后续可根据真实用户证据增加可选测试策略。

manifest 从 0.5.0 起声明 `network` 权限，运行时仍必须检查 Blender 在线访问开关。完整 AI 版的分发继续以本地 ZIP 为主，官方扩展平台兼容性单独评估。

## 验证

- 纯 Python 测试覆盖 URL 安全规则、认证头、成功响应、401/403、429、5xx、断网、超时、超大响应和错误 JSON。
- 日志回归测试证明 Key、Authorization 和 Token 字段被脱敏。
- Blender 集成测试证明 Key 属性属于 `WindowManager` 而不是 `Scene`，保存 `.blend` 后找不到测试 Key 字节。
- 子进程连接测试期间场景指纹保持不变；取消、超时和错误结果不创建计划、不执行事务。
- 隔离安装包通过 Blender 4.5.12 LTS 的注册、禁用与重新启用测试。
